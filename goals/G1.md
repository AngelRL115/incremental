# Goal G1: MVP jugable de navegador

## Instrucción humana y límites
- Implementar Phase 3 como juego incremental original, integrando Phase 2 sin reescribirlo.
- Identidad “Observatorio editorial” seleccionada por el usuario; no reabrir dirección ni scope.
- Mantener el MVP local single-player, sin backend, cuentas, auth, PII, tracking, monetización, publicación ni deploy.
- El usuario autorizó el commit inicial del snapshot de producto. No se autorizó
  despliegue; no ampliar esa autorización a commits o releases posteriores.

## Señales y composición
- Señales: UI web de usuario, visualización Canvas, persistencia/import/export local, progreso offline/prestigio, accesibilidad, QA browser.
- Incluidos: `frontend-engineer` (implementación), `product-designer`/`ui-designer` (consulta de experiencia e identidad), `tech-lead` (consulta de límites de integración), `security-engineer` (review acotado de import/save y exclusión multi-tab), `accessibility-specialist` (gate a11y), `qa-automation` (automatización), `qa-tester` (gate funcional), `git-specialist` (solo preparación de cierre exigida por el flujo).
- Aprobación de producto: `product-owner` conserva el alcance P0; no hay decisión de producto nueva en este plan.
- Excluidos: ver `project/STATE.md`; sus ausencias se justifican por las señales negativas del goal.

## NFR y criterios globales
- Economía del juego exclusivamente por el engine existente: ni fórmulas duplicadas ni dependencia de `requestAnimationFrame` para progreso.
- Canvas 2D aislado de la economía, DPR-aware, con cleanup; reduced motion/efectos no altera estado ni tasa económica.
- T2 UI: loading, empty, error y success visibles y accionables; errores de usuario sin stacktrace.
- Responsive sin scroll horizontal a 360, 390, 768, 1024 y 1280 px; controles táctiles ≥24×24 px (44×44 recomendado).
- WCAG 2.2 AA en el flujo P0: contraste normal ≥4.5:1, UI/foco ≥3:1, teclado y foco visible, labels/nombres accesibles y ningún estado comunicado solo por color.
- Sin PII, tracking, secretos ni telemetría. Datos importados se validan; error no puede sobrescribir el save válido.
- Gate T2: build/typecheck y tests, QA de happy/empty/error, review Security ligera en la superficie import/save/multi-tab y gate a11y; evidencia en paths/resultados. No hay gate de producción/release.

## AC medibles Given / When / Then

### F1 — B1: inicio, ticker y escena
1. **Given** no existe save y el engine crea un estado nuevo, **When** abre el juego, **Then** se muestra 25 Charge, Seed Array nivel 1 y 4 Charge/s según `createNewGameState()`; el primer render de escena no modifica ninguno de esos valores.
2. **Given** la partida está activa, **When** avanza el tiempo del engine con el ticker, **Then** recursos/tasas cambian según el engine aunque se pause o ralentice RAF; el renderer solo anima.
3. **Given** cambia el tamaño/DPR del viewport, **When** Canvas se redimensiona, **Then** sus dimensiones de backing store corresponden al DPR actual y recursos/niveles/timestamps permanecen idénticos.
4. **Given** falla la inicialización del estado o del renderer, **When** la pantalla intenta arrancar, **Then** comunica un error recuperable y opción de reintentar; no muestra progreso ficticio ni deja un loop RAF/ticker duplicado.

### F2 — B2: HUD, compras y unlocks
1. **Given** saldo suficiente y upgrade habilitado, **When** se confirma compra, **Then** el engine actualiza saldo, nivel y tasa; la UI refleja esos valores en ≤1 actualización de estado.
2. **Given** upgrade locked, saldo insuficiente o límite máximo, **When** se muestra el control, **Then** está deshabilitado/no ejecutable y explica cuál condición aplica; un estado sin upgrades disponibles indica el siguiente objetivo.
3. **Given** saldo insuficiente o compra repetida rápidamente, **When** se activa varias veces, **Then** ninguna operación deja saldo negativo ni repite una compra inválida; el error/razón es visible y la economía permanece consistente.
4. **Given** se alcanza el umbral Echo de 250 Charge, **When** el engine reporta el unlock, **Then** la UI lo revela con el coste real del engine y una alternativa textual además del color/animación.

### F3 — B3: guardar, restaurar, exportar/importar
1. **Given** una partida válida, **When** ocurre autosave y luego reload, **Then** se restaura el mismo snapshot económico y `savedAt`; feedback indica guardado/restauración exitosa.
2. **Given** JSON malformado, envelope inválido o versión futura, **When** el usuario importa/abre el save, **Then** ve un error accionable, el save válido anterior no se reemplaza y no se ejecuta contenido del archivo.
3. **Given** storage falla por cuota o acceso denegado, **When** se guarda/restaura, **Then** se informa el error sin afirmar éxito; la sesión en memoria puede continuar y se ofrece recuperación/exportación cuando esté disponible.
4. **Given** save válido, **When** se exporta y reimporta, **Then** el snapshot validado se conserva; borrar/reiniciar requiere confirmación explícita y cancelar mantiene el save sin cambios.

### F4 — B4: offline y prestigio
1. **Given** save con timestamps controlados y retorno después de una pausa, **When** se calcula offline, **Then** se muestran elapsed, tiempo capado si aplica, recursos otorgados y automatización desde las funciones del engine.
2. **Given** dos pestañas intentan reclamar el mismo intervalo, **When** ambas restauran a la vez, **Then** como máximo una aplica y persiste ese gap offline; el resultado determinista se verifica en test con dos contextos.
3. **Given** la lease/claim o persistencia falla, **When** se procesa el gap, **Then** la UI reporta conflicto/error, no concede progreso dos veces y da una ruta de reintento/recovery sin descartar el save válido.
4. **Given** prestige disponible, **When** se previsualiza y se cancela, **Then** recompensa, recursos y progreso permanecen byte-a-byte equivalentes al estado previo; **When** se confirma una vez, **Then** el reset del engine ocurre exactamente una vez, Conduit permanente permanece y la tasa posterior corresponde al engine.

### F5 — B5: accesibilidad, responsive e identidad
1. **Given** cualquiera de los viewports 360, 390, 768, 1024 o 1280 px, **When** se recorre el journey, **Then** no hay scroll horizontal ni control esencial fuera del viewport y los objetivos táctiles miden ≥24×24 px.
2. **Given** usuario opera solo con teclado, **When** recorre HUD, compras, import/export, modal prestige y errores, **Then** cada acción tiene nombre/label accesible, orden lógico y foco visible que no queda oculto; errores se asocian con el control.
3. **Given** tokens de texto, fondo, UI y foco de la pantalla listón, **When** se mide el contraste, **Then** texto normal alcanza ≥4.5:1 y estados/componentes/foco ≥3:1; ninguna información se transmite solo por color.
4. **Given** `prefers-reduced-motion: reduce` o reduced-effects está activado, **When** se renderiza o alcanza un hito, **Then** se reducen/detienen movimiento decorativo y partículas no esenciales sin cambiar economía ni bloquear controles.
5. **Given** Visual QA de identidad, **When** se compara la pantalla listón y estados empty/error/loading en breakpoints, **Then** se aplica “Observatorio editorial”, hay jerarquía editorial propia, SVG original cuando corresponda, cero emojis y cero hallazgos Generic Blocker.

### F6 — B6: validación integrada
1. **Given** instalación reproducible del repo, **When** se ejecutan `npm run build`, `npm test` y `npm run balance`, **Then** los tres comandos terminan con exit code 0 y Vitest conserva todas las pruebas previas (23 según baseline de bootstrap) más las nuevas.
2. **Given** build browser con fixture/reset determinista y reloj inyectable, **When** Playwright ejecuta el journey P0 completo, **Then** finaliza en navegador sin error de consola y registra resultados/versión de build.
3. **Given** un viewport móvil, import inválido y compra rápida, **When** corren las regresiones, **Then** no aparece overflow horizontal, el save válido permanece intacto y el saldo no se hace negativo.
4. **Given** los resultados de tests y checks a11y, **When** `qa-tester` revisa AC, **Then** registra pass/fail por AC y bloqueantes encontrados; no se declara sign-off con checks ausentes o rojos.

### F7 — Cierre de slice
1. **Given** F1–F6 con evidencia, **When** `git-specialist` prepara el cierre, **Then** entrega resumen del diff y propuesta de commit sin ejecutar commit, push o deploy; si no existe `.git`, registra la precondición faltante en vez de inicializarlo.
